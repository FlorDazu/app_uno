# AGENTS.md: AppUno (Angular 22 + SSR)

## Commands

| Action | Command |
|--------|---------|
| Start dev server | `ng serve` — serves at `http://localhost:4200` |
| Build (production) | `ng build` — outputs to `dist/`, uses production config |
| Build (development) | `ng build --configuration development` — disables optimization |
| Watch build | `ng build --watch --configuration development` |
| Run unit tests | `ng test` — runs Vitest across all spec files |
| Run SSR server | `node dist/app_uno/server/server.mjs` — uses PORT env var (default 4000) |
| SSR via npm script | `npm run serve:ssr:app_uno` — runs `node dist/app_uno/server/server.mjs` |

**Order matters**: `lint -> typecheck -> test -> build -> serve`. The Angular CLI wraps these, but if running raw commands, run typecheck (`ng build`) before tests.

## Project structure

This Angular 22 SSR project enforces a strict component-service separation with interface files:

- Each feature has its own directory under `src/app/`
- **Component**: `*-component.ts`, `*-component.html`, `*-component.css` (HTML **must be separate** from TS)
- **Service**: `*.service.ts`, se creará una carpeta (`services/`) la cual guardará todos los archivos de service
- **Interface**: `*.interface.ts`, se creará una carpeta (`interfaces/`) la cual guardará todos los archivos de interface
- Services are provided via `provideService()` or `provideExperimentalZChangeDetection()` as needed
- `src/app/app.ts` - root component (bootstrapped in `main.ts`)
- `src/app/app.config.ts` / `src/app/app.config.server.ts` - application configuration
- `src/app/app.routes.ts` - client routes (currently empty)
- `src/app/app.routes.server.ts` - server-only routes: all paths render with `RenderMode.Prerender`

- **Component template rule**: The HTML template must live in a `*.html` file imported via `styleUrl`/`templateUrl` - never inline the template in TypeScript file.

**Important**: The app uses Angular SSR (Universal). The server renderer prerenders all routes. Changes to `app.routes.server.ts` affect server-rendered output.

**Note on component-service-interface structure**: This repo is a minimal Angular CLI-generated app without established service pattern. If adding services, place them under `src/app/` following the pattern: `<nombre>.service.ts` for the service class and `<nombre>.interface.ts` for the interface. Templates are always separate `.html` files from their `.ts` components.

## Testing

- `ng test` runs Vitest. Config is in `tsconfig.spec.json` (vitest/globals types).
- Unit tests live under `src/app/app.spec.ts`.
- Test fixture pattern: `TestBed.createComponent()`, `fixture.whenStable()` for async stability.
- No integration test fixtures or external services required.

## Codegen / scaffolds

- Angular CLI generics are available: `ng generate component <name>`, `ng generate directive <name>`, etc.
- No custom schematics configured (`schematics: {}` in `angular.json`).

## Environment / infra

- Server listens on `PORT` env var (default 4000), defined in `src/server.ts:55`.
- Angular CLI uses `npm` as package manager (set in `angular.json`).
- No `.env` files or special env loading in the repo.

## What to avoid / common pitfalls

- **Do not edit `src/index.html` path references without rebuilding** — the `base href` is `/` and assets are resolved relative to it.
- **SSR changes require a full build** — `ng build` produces `dist/browser` and `dist/server`; the Express server reads from `dist/browser`.
- **Unit tests exclude spec files from `tsconfig.app.json`** — they have their own `tsconfig.spec.json` with vitest globals.
- **The `app.html` template contains inline CSS with `:host` styles** — component styles are scoped via `styleUrl: './app.css'` which compiles to the global `src/styles.css`.
- **`app.routes.ts` is empty** — all routing is handled server-side via `app.routes.server.ts`. Client-side routing is not configured.
